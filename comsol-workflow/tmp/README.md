# 算法试验区

新数值、几何或可复用分析算法先写入 `<topic>/<algorithm>.py`；主题和能力名使用
lower_snake_case。算法可导入 `comsol_workflow`，正式核心不得反向导入 tmp。
导入无求解副作用；从仓库根按包执行，不添加包子目录到 sys.path。

调用算法完成计算、分析或画图的编排脚本位于 `tests/<topic>/`，纯检查位于其 checks。
只有经过需求、来源/配置身份、单位/相位、数值和适用域验证，且适合长期复用时才晋升；
优先合入现有核心所有者，更新调用者和检查，消除重复实现并回填工程 Spec。
具体步骤见 [AGENTS](../AGENTS.md#新算法与新脚本的两条晋升通道)。

`.work/<task_id>/` 存合成输出、staging、运行日志与缓存，源码不能只存 .work。
真实计算结果遵守授权根及职责分类，不因算法在 tmp 而移入这里。
只清理本轮 .work 产物，不全量删除算法源码。

`archive/` 保存 2026-10-09 归档的原内容。清单为 archive_manifest_20261009.json；
旧准备清单、历史绝对路径和哈希保持原样，不能直接据此自动恢复计算。
不把 archive 用作新代码/输出目录，不自动迁移或清空其中内容。

随后按用户授权清理了已核实冗余；原归档清单记录当时身份，当前分类及替代/恢复路径见
[逐项清单](../docs/spec/staging_cleanup_inventory_20261009.json) 和 [审查报告](../docs/staging_cleanup.md)。
P4（archive/s4_20260916-gamma-v2/review.py）为待用户决定的评审能力候选，保持原件，不自动晋升。
历史 audit、参数快照及旧数值 backup 保留，不是新算法或可随意删除的缓存。
